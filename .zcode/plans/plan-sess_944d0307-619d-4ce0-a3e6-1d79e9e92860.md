## Step 1 — `scripts/run_benchmark.py` (Milestone 2 core)
The harness runner:
- Loads `squad2_dev_150.jsonl`; for each item: build an isolated per-item index via `index_texts(item["contexts"], collection=f"bench_{item_id}")`, run `answer_question(question, store=that_store, item_id=..., run_tag="squad2_dev_150_m2")`, for **both arms** (`baseline=False` guarded, `baseline=True` control). Clear the throwaway collection after each item to bound disk use.
- **Resumable**: on start, query telemetry for completed `(item_id, arm)` pairs under the run tag and skip them; `--limit`, `--tag`, `--arm` CLI flags. Progress printed per item.
- Handles Ollama errors/timeouts per item without killing the sweep (llama3.1:8b on 8 GB VRAM, temperature 0).

## Step 2 — `scripts/eval_benchmark.py` + SQuAD metrics (Milestone 2)
- Join telemetry rows (`run_tag`+`item_id`) to benchmark labels; compute standard SQuAD 2.0 EM/F1 with the official normalisation (lowercase, strip articles/punct) + a no-answer convention (prediction = abstain message or `INSUFFICIENT_CONTEXT` counts as empty).
- Report per arm (guarded vs baseline): exact match, F1, and the project-specific confusion table on unanswerables — abstained (correct) vs hallucinated (answered) — plus answerable coverage (answered vs over-abstained). Write `reports/benchmark_m2.json` + a markdown summary table.
- Milestone 2 is "done" when: guarded arm abstains on most unanswerables while baseline answers them (hallucination rate), and guarded F1-on-answerables doesn't collapse vs baseline (abstention cost).

## Step 3 — `scripts/calibrate.py` (Milestone 3a)
- Fit Gate A on labelled answerable/unanswerable: sweep thresholds over `rerank_relevancy` alone (current primary signal) AND a logistic regression over the 4 recorded features (`rerank_relevancy`, `top_similarity`, `mean_similarity`, `similarity_margin` — all already persisted, which is why they exist). Pick operating points at chosen target(s) (e.g. maximise F1 on the answerable/unanswerable decision, or ~90% unanswerable recall).
- Fit Gate B on grounded/ungrounded (baseline-arm rows give grounded answers on answerables; fabrications come from unanswerable items the baseline answered anyway — the classic RAG hallucination proxy; also use `n_conflicts`/`n_baseless`). Sweep `gate_b_threshold`.
- Write `reports/calibration.json` (thresholds, feature weights, ROC/AUC, chosen operating point, dataset provenance, run_tag) and update `src/config.py` defaults + README to the calibrated values. `thresholds_json` telemetry already guards against pooling rows across old/new thresholds.

## Step 4 — `scripts/risk_coverage.py` (Milestone 3b)
- From the telemetry rows: sort by composite/gate scores, compute risk–coverage curves (selective-accuracy vs abstention budget), AURC, and coverage@risk points — for the guarded arm, the baseline arm, and an oracle-abstention reference.
- Emit `reports/risk_coverage.json` + matplotlib figures (PNG in `reports/figures/`): risk–coverage curve per arm, score-distribution histograms (answerable vs unanswerable) showing Gate A separation, reliability of composite vs correctness.

## Step 5 — `scripts/judge_agreement.py` (Milestone 3c)
- Re-run a 50-item subset with `RAG_SCORER=both` (separate run_tag, e.g. `squad2_dev_50_judge`) so DeepEval/qwen2.5 shadow-scores sit alongside NLI in telemetry (`llm_relevancy`/`llm_faithfulness` columns already exist).
- Compute: Pearson/Spearman correlation per gate, Cohen's κ on the pass/fail decision at calibrated thresholds, disagreement rate with a few illustrative quotes, and latency cost of the judge vs NLI. Write `reports/judge_agreement.json` + markdown summary.
